# Sitemap flag system — deploy & migration handoff

_Generated by the `stackshift-sitemap` skill. This is the human work order to
finish rollout. The site behaves exactly as before until the migration runs and
the site redeploys._

## What changed

Editors now control sitemap membership per page via an **"Add to sitemap"**
toggle in Studio. Only pages toggled ON appear in the sitemap; a page toggled
back OFF is served a `noindex` robots meta so search engines drop it. The
sitemap regenerates on every production build at `{{OUTPUT_PATH}}`.

## Required before / at deploy

1. **Environment.** `NEXT_PUBLIC_SITE_URL` must be set in the production deploy
   environment (e.g. `{{SITE_URL}}`). The production build **fails by design** if
   it is unset (prevents a localhost sitemap shipping to production).
2. **Seed the flags (one-time migration).** Until existing pages are flagged, the
   generated sitemap is empty and the build's SAFETY STOP will fail. Run from a
   developer machine with the Sanity **write** token available:

   ```bash
   # dry run first — review the table of documents that would be flagged
   NEXT_PUBLIC_SITE_URL={{SITE_URL}} SANITY_API_WRITE_TOKEN=… yarn sitemap:migrate
   # then apply
   NEXT_PUBLIC_SITE_URL={{SITE_URL}} SANITY_API_WRITE_TOKEN=… yarn sitemap:migrate --execute
   ```

   > The dataset is private: without a token the migration reports "0 documents"
   > (a silent empty result, not an error). A non-zero dry-run count confirms the
   > token is working.

3. **Hosting UI check.** If the project previously used a crawler-based sitemap
   plugin, confirm it is not still installed in the hosting dashboard UI —
   {{HOSTING_UI_NOTE}} — otherwise it may overwrite the generated sitemap.

## After deploy — verify

- `curl -s {{SITE_URL}}/{{OUTPUT_PATH}}` returns the generated sitemap (static file).
- `curl -s {{SITE_URL}}/robots.txt` lists the sitemap; no new `Disallow`.
- Any retired runtime sitemap route now returns 404 — de-register it from Google
  Search Console if it was submitted there; submit `{{OUTPUT_PATH}}` if not already.
- Over the following weeks, GSC "Page indexing" shows pages toggled OFF moving to
  "Excluded by 'noindex'".

## Ongoing

- New pages are OFF by default (absent from the sitemap, still indexable). Editors
  toggle ON to include a page; toggle OFF to remove **and** de-index it.
- The sitemap file updates on the next production build; a flag flip's `noindex`
  meta takes effect within ~a minute via ISR/webhook revalidation.
